# AI 简历生成器

把口语化的个人经历，交给大模型整理成结构化内容，再由程序排版成可直接投递的 **A4 Word 简历**。

关键词：结构化输出 · 幻觉抑制 · 自动评测 · python-docx 版式渲染

---

## 它解决什么问题

求职者写得出来的通常是「大白话」，投得出去的必须是「简历体」。中间缺的不是文笔，是两件事：

1. **内容重组**——把流水账压成「领起词 + 动作 + 方法 + 结果」的短句
2. **版式固定**——A4 纸、双栏信息区、深蓝色块标题、时间左对齐 / 机构右对齐

多数「AI 简历」工具只做了第 1 步，输出一段 Markdown，用户还要自己粘进 Word 重排一遍。
这个项目把第 2 步也做了：**模型只负责内容，版式由代码控制**，产出的文件直接可用。

## 工作流程

```
口语素材
   ↓  系统提示词强约束
结构化 JSON  ──→  解析 / 兜底清洗  ──→  python-docx 渲染  ──→  .docx
   ↓
自动评测（20 条用例）
```

关键设计：**不让模型输出排版指令**。早期版本让模型直接写 Markdown，结果标题层级、加粗位置、换行都不可控，还出现过整段带解释文字的情况。改成输出 JSON 后，版式完全由代码决定，模型只填内容字段。

## 功能

- 大白话素材 → 一键生成 `.docx`，版式无需二次调整
- **信息缺失写占位符**（`[手机号]`、`[学校名称]`），而不是编造
- 界面提示剩余占位符数量，提醒补全后再投递
- 数值、奖项、公司名只从素材里取，不自行编造
- 超时与重试交由 SDK 的指数退避处理，Key 失效 / 余额不足有明确提示
- 生成结果存于 `st.session_state`，切换控件不会丢失

## 评测

不靠「看着还行」判断效果，而是用 **20 条覆盖不同背景的用例**跑分，全部自动计算：

> 信息齐全 / 缺姓名 / 只给电话 / 无正式实习 / 转专业转行 / 空档期 / 大专 / 海外硕士 / 多段实习 / 纯在校经历 / 成绩含糊 / 课程与实习时间冲突 / 直博 / 临床实习 / 退役军人复学 / 社招五年经验 / 师范临聘 / 数据密集 / 中英混排

| 指标 | 数值 | 说明 |
| --- | --- | --- |
| JSON 解析成功率 | **100.0%** | 20/20 原文可直接 `json.loads` |
| 必填字段完整率 | **100.0%** | 四个顶层字段 + entry 五键齐全 |
| 　其中 name | 90.0% | 2 条素材本身未给姓名 |
| 　其中 contact | 95.0% | 1 条素材只给电话未给邮箱 |
| 姓名与素材一致 | **100.0%** | 仅在素材提供姓名的用例上统计 |
| 年份幻觉免疫率 | **100.0%** | 输出中的年份均能在素材中找到 |
| 综合得分 | **100.0 / 100** | 0.3×解析 + 0.4×字段 + 0.3×幻觉 |
| Word 渲染成功率 | **100.0%** | 实际调用渲染链路 |
| 调用出错率 | **0.0%** | 无异常 / 超时 / 空输出 |
| 延迟 P50 / P95 | **1610ms / 2060ms** | 端到端单条 |

上表由 `python eval.py` 自动生成，原始数据见 [`eval_results/report.md`](eval_results/report.md)。

**关于 90% 和 95%**：这两项不是缺陷。对应的是「素材未提供姓名」和「只给电话未给邮箱」两类用例，模型按设计输出占位符而非编造，属于预期行为——用例通过 `required_fields` 声明本条真正必需的字段，避免把「素材里本来就没有」算成模型的错。

### 指标口径

- **JSON 解析成功率**：三档统计。`strict` = 原文直接解析成功；`fenced` = 去掉 Markdown 代码块包裹后解析成功；`salvaged` = 从混杂文本中按括号配对找回。任一成功即计为解析成功。分档是为了区分「模型守约」和「靠兜底救回来」——只看总分会把后者掩盖掉。
- **必填字段完整率**：`name` / `intent` / `contact` / `sections` 非空且不是纯占位符；`sections` 还要求每个 entry 带齐 `period/org/role/title/bullets`。
- **年份幻觉**：正则抓取输出中所有 `19xx` / `20xx`，凡不在素材年份集合中的都算多出，每个扣 15 分。

### 复现

```bash
python eval.py                 # 全量 20 条，报告写入 eval_results/
python eval.py --limit 3       # 先试 3 条
python eval.py --adapter mock  # 不调模型，自检测评器本身
python eval.py --dry-run       # 只校验用例格式与参数，不发请求
```

支持失败门禁，可接入 CI：

```bash
python eval.py --min-json-rate 0.95 --min-field-rate 0.95
```

## 快速开始

```bash
pip install -r requirements.txt
streamlit run web_app.py
```

API Key 放在 `.streamlit/secrets.toml`（已被 `.gitignore` 排除）：

```toml
DEEPSEEK_API_KEY = "sk-..."
```

也可以设同名环境变量 `DEEPSEEK_API_KEY`，两者都没有时界面会显示输入框。


## 设计取舍

| 决定 | 理由 |
| --- | --- |
| 输出 JSON 而非 Markdown | Markdown 表达不了「时间右对齐」「板块色块」这类版式，且模型对标题层级控制不稳定 |
| 版式写死在代码里 | 简历的版式不需要"智能"，需要的是每次完全一致 |
| 缺失信息写占位符 | 编造学校名或数字在投递场景会直接翻车，宁可留空让用户自己填 |
| 表格边框画成白色 | 直接写"无边框"时 LibreOffice 会回落到默认灰线，显式白色可保证跨 Word / WPS / LO 观感一致 |
| 评测用例自己写 | 简历场景没有公开基准集，只能按真实素材形态构造覆盖 |

## 已知限制

- 评测用例由作者构造，存在**过拟合风险**；结论只对当前用例集成立，不代表通用能力
- 幻觉检测目前只覆盖**年份**，尚未覆盖公司名、数字、奖项
- 只测了 `deepseek-chat` + `temperature=0.3` 单一组合，未做跨模型对比
- 内容超过一页会自然分页，未做"应届生压一页"的自动精简
- 没有 JD 匹配、没有多轮修改，属于一次性生成
